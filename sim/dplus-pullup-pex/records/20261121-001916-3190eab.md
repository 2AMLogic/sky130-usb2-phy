- **The failure mechanism is the committed layout's own interconnect, not the devices and not the extractor's device recognition**: `layout/analog/gen_common.py`'s `res_generic_po` draws each ladder segment as a poly bar with a contacted poly head 0.8 um x 2 um outside the `poly_res` marker on each end. The extraction assigns those heads (unsaliced poly plus the licon/mcon contact stack) to the *nets*, and the extracted netlist carries terminal stubs of ~1.6-2.1 kohm on the ladder nodes (largest: `R_15_t0` 2057.0 ohm, `R_15_t1` 1976.5 ohm, `R_7_t41` 1721.5 ohm, the VSS head stubs 1653.1 ohm each; 1051 parasitic R cards total). The enabled path (VPU -> enable switch -> RBASE -> bypass switches -> DP) crosses several such nodes, so every trim code gains multiple kohm: code 15 moves ~1116 -> 3720.78 ohm at tt and code 0 (full ladder, schematic 1894 ohm) moves to 16746.9 ohm. The layout is LVS-matched 1:1 and DRC-clean per its committed record, so this is the committed geometry's real measured behaviour under the pinned extraction deck. Fix direction in #414 (land the heads on li1/met1 with a low-resistance contact array and jumper node-to-node in metal, or equivalent), then re-run this bench.
- **PEX model scope**: lumped, quasi-static RC; the series-R half is first-order (one lumped star per net, not a distributed ladder), so the measured stub values are the model's reading of real geometry -- a distributed extraction would distribute the same total resistance. The absolute failure margin (every code at least 2.35x the window's upper edge at its best) is far outside any first-order versus second-order model difference.
- **Two-corner subset**: stated above; the failure holds at both requested corners, so the subset is not what hides or produces it.
