## Method

- Stimulus: identical to the committed threshold bench (tb.json measurements, analysis and checks derived from sim/se-receiver-dp-thresholds/testbench/tb.json; the dc sweep of the line input 0-3.0 V at 1 mV, supply = swept I/O rail vsup). Values are compared and reported in raw klt-side units (V and A; the committed record displays isup in uA -- multiply by 1e6).
- Deck restructure (the change that makes the bench `klt pex`-runnable, same as #281): the DUT moves from the request-level `include` array into exactly one in-deck `.include` line naming the pin-order shim described under Netlist provenance, and the receiver instance line's nets are reordered to the extracted pin order.
- Schematic-side equivalence gate (exact pairs): before trusting any delta, the run's schematic leg must reproduce the committed record at exactly the requested (corner, measurement) pairs -- derived from this bench's own tb.json, not from the 225-corner reference: 2 corners x 7 measurements = 14 rows, each present exactly once, finite, and within relative deviation 1e-6 of the committed raw value. This run: 14/14 rows ok at relative deviation 0 (exact double equality).
- Measurement portability (why 7 measurements, not the bench's 8): the committed bench's `vref_v` probes a node inside the DUT by instance-qualified vector (`.meas dc ... FIND v(xrx.vref)`); the extracted netlist renames internal nets to synthesized hub names, so that row errors the whole envelope on the extracted leg (klt pex `no_such_vector`). It is deliberately absent from this bench; the discovery run (20261121-000805-cd85ff5, its own campaign in the artifact store) had the schematic leg reproduce the committed vref_v at both corners (1.40287 V at tt, 1.27507 V at ff_lh) before the row was removed. `vref_v` is the bench's own sanity probe, explicitly not a spec row; the threshold it feeds is measured directly by vth_v on both legs. Tool gap filed as 2AMLogic/klayout-tools#6990.
- Corner set: tt plus the binding corner of the committed 225-point record -- the process section ff_lh is one of the pinned library's resistor/capacitor parameter-set sections (ll/hh/hl/lh), so the requested corner is a resistor-set section, which klt sim maps to the same pinned-library .lib section the schematic record used (evidence.json `sections` of that record). The deltas at other corners are not bounded by these two; the full 225-point post-layout run is the follow-up that would make that claim.
- Grading limits: the request declares limits only where the bench's criteria are supply-absolute (vth_*: [0.8, 2.0] V; isup_*: 1e-6..5e-4 A). The output-level criteria (>= 0.9 x vsup / <= 0.1 x vsup), the single-crossing criterion (vth_last_v == vth_v within one 1 mV step) and the endpoint-strictness of the crossing window are supply-relative or cross-row, so they are evaluated per corner in grading.json (all pass; the table below carries the same values).
